# Phase 8: Core Keys as Form State, No Mapping Layer

**Date:** 2026-11-23 | **Base:** `25april` at `d66c8ecd` | **Goal:** form state uses core keys (`Bolt.Diameter`, not `bolt_diameter`), as the desktop does. Values the desktop derives come from the core's own tables. The design request, the `.osi` file and the stored project become the same dict. Purlin is out of scope.

## Desktop target
- `osdag_gui/ui/windows/template_page.py:1742-1808` (`design_fn`) builds the design dict from the dock, keyed by `input_values()` keys. If Additional Inputs was saved, its values are merged in. Otherwise it walks `input_dictionary_without_design_pref()`: a tuple with source `'Input Dock'` copies the dock value; `(None, [...], '')` calls `get_values_for_design_pref(key, dict)`.
- The derivation table already exists in the core: `input_dictionary_without_design_pref`, `get_values_for_design_pref`, `input_dictionary_design_pref`, `refresh_input_dock`. The web must use it, not write another.
- Load (`setDictToUserInputs`): every key that is not an `input_values()` key goes to `design_pref_inputs`. Save: the full design dict as YAML. Changing a dock key that feeds an `'Input Dock'` copy clears all prefs.

## Where field names are translated today
**Frontend (12 sites):** `buildSubmissionParams` in 18 builder files (456 `[KEY_*]` entries: 187 pure renames, 269 with value logic; 674 `inputs.<field>` reads); field keys/`inputKey`/`defaultInputs` in the configs; `osiMapperTracer.js`; `osiNormalizer.js`; `osiLoader.js` (aliases and value normalisers); dead `buildOsiContent`; `INPUT_KEY_TO_LIST` (20); three divergent `.osi` save paths (`UnifiedDropdownMenu` writes web names); `designPrefModuleConfig.js` (25 modules); modals and pref hooks (about 60 refs); `InputSection.jsx` name heuristics (376, 429, 443-444); `DesignReportModal.jsx:156-161` treats any dotted key as already transformed.
**Backend (4 sites):** `osi_files.py` (38-entry table, normaliser, export flattener); `sync_merge.py` (`_FRONTEND_TO_CORE_KEY_MAP`, `_SECTION_KEY_MAP`, `_MATERIAL_SYNC_RULES`, `_CORE_CLASS_MAP`); session-name maps; two adapters with residual aliases (base plate, beam-beam end plate).

**Shapes to handle:** 57 cases of one field feeding several core keys; 8 of one core key feeding several fields (shear sections by connectivity); the same web name meaning different core keys in different modules.

**Likely latent wire bugs (confirm in S0e; fix in separate PRs):** shear modules send `Material` from `connector_material` after pref merge; tension sends `KEY_SEC_MATERIAL` from `inputs.material` so the modal's pref is dropped; simply supported sends `section_material`; `UnifiedDropdownMenu` writes web names to `.osi`; base plate prefs never reach the wire.

## Target design
- State: `inputs` (core dock keys), `prefs` (core keys from `input_dictionary_design_pref`, empty until saved or loaded), `ui` (allSelected, selectionStates by core key; connectivity only in `inputs[KEY_CONN]`).
- `buildSubmissionParams` becomes `finalize(dict, ctx)`: value logic only. "All" expansion is generic from `field.dataSource`.
- `toDesignDictionary(config, state, lists)` is the design request, the `.osi` content and the project `inputs_json`. `fromDesignDictionary` splits it back.
- Derivation: backend `apps/core/design_dictionary.py` (`pref_tables(module_id)`, `derive(module_id, dock, prefs)`, a port of desktop `design_fn`); frontend `generated/designPrefTables.js` generated by `scripts/gen_core_keys.py` (static data: dock keys, pref tabs, dock copies, computed keys, section sources). Tolerate core defects: duplicate `KEY_DP_DETAILING_EDGE_TYPE` in `tension_bolted.py:195`, duplicate dict key in `member.py:2537-2547`, `KeyError` from `get_values_for_design_pref`.

## Risks
Saved projects stop loading after S3 (test data; migration nulls them). Pref sync is the least tested path. Desktop clears all prefs on a driver change; the web clears only materials. `.osi` files saved by the web before S3 lose their prefs. Many-to-many fields keep today's wire via explicit `wireCopies`. Shear connectivity-split fields must reset on a connectivity change. `String()` coercions turn missing keys into `"undefined"`; pin, do not fix, in rename slices. Purlin keeps web names with a documented fallback. Base plate prefs never reach the wire today; S6 changes that.

## Recommendation
Do S0 now (closes real test gaps, about a day). Do S1 to S4 (stop point A): six imperative mapping sites become one declared, tested table per module, `.osi` becomes desktop-readable, projects store the design dict, pref sync uses core tables. Defer S5 (mostly cosmetic, large churn in the least-tested code) until forms are generated from the core's `input_values()`. Treat S6 as a product decision needing before/after sign-off.
